Dit system har to primære problemer:
Table
Problem	Effekt
1. Modality mismatch	Vision-tekst sammenlignes med produkt-billeder (text→image) i stedet for text→text
2. Løst type-filter	"Stol" matcher bogreol, sofa matcher lampe — types låser ikke kategorien

    ↓

Fejl 1: Modality Mismatch (Den største årsag til dårlig match)
Hvad der sker nu
TypeScript
Copy
// Din query embedding er TEXT-baseret (fra GPT's beskrivelse)
const queryVector = await getClipTextEmbedding("grey sofa scandinavian");

// Du søger mod IMAGE embeddings af produktfotos
SELECT * FROM products ORDER BY vector_clip <=> queryVector
Hvorfor det fejler
CLIP er cross-modal — den KAN sammenligne tekst og billeder — men præcisionen er lavere end text→text:
Table
Sammenligning	Forventet præcision	Årsag
Text → Text (samme model)	85-92%	Identisk domain
Text → Image (cross-modal)	55-70%	Det du har nu — domain gap
Image → Image	90-95%	Identisk domain
"Grey sofa" som tekst matcher et billede af en sofa OK — men det matcher også et billede af en stol med gråt stof eller et billede af en grå lampe, fordi CLIP ser farver og teksturer, ikke kategorier.
Konkret eksempel på fejl
plain
Copy
Vision: "Grå sofa, 3-personers, stof"
→ Text embedding: [0.12, -0.34, 0.89, ...]

Database match mod vector_clip (BILLEDE-embeddings):
- Sofa-billede:     cosine = 0.82 ✅
- Seng med gråt stof: cosine = 0.74 ❌ (farve+tekstur match!)
- Grå lampe:         cosine = 0.71 ❌ (farve match!)
- Bogreol i gråt:    cosine = 0.68 ❌ (farve match!)
Løsning: Dual-vector strategi
Du har brug for begge kolonner i databasen:
sql
Copy
vector_clip  — IMAGE embedding af produktfoto (du har den, 243.897 stk.)
vector_text  — TEXT embedding af produktnavn (name_en) — GENERERES NU
Matcher skal prioritere vector_text:
TypeScript
Copy
// 1. Generer TEXT embedding af vision-beskrivelsen
const queryVector = await getClipTextEmbedding("grey sofa scandinavian");

// 2. Søg primært i vector_text (text→text = præcist)
const distanceExpr = sql`
  CASE 
    WHEN ${products.vectorText} IS NOT NULL 
    THEN ${cosineDistance(products.vectorText, queryVector)}
    ELSE ${cosineDistance(products.vectorClip, queryVector)}  -- fallback
  END
`;

// 3. Order: nærmeste først
ORDER BY distanceExpr ASC
Forventet forbedring: 55-70% → 80-90% match-præcision
Fejl 2: Løst Type-Filter (Årsag til kategori-forvirring)
Hvad der sandsynligvis sker nu
TypeScript
Copy
// SLAPT filter — type er ét af mange kriterier
conditions.push(sql`${products.tags}->>'type' = ANY(${parsed.types})`);

// Hvis ingen produkter med type "sofa" → fallback til andre typer
// Resultat: "stol" → matcher bogreol, kommode, lampe...
Hvorfor det fejler
Din tags->>'type' er ikke stram nok. Når YOLO detekterer "stol" og GPT-4o-mini beskriver "grå stol med træben", så:
Dansk→engelsk mapping er kritisk — hvis "stol" ikke mappes korrekt til "lounge_chair" i databasen, matcher den intet
Fallback-logik åbner for alle produkter når type ikke findes
YOLO + GPT uenighed — YOLO siger "sofa", GPT siger "lounge chair" → mismatch
Løsning: Mandatory type + strict mapping
TypeScript
Copy
// A. Type er MANDATORY — ingen fallback, ingen undtagelser
if (parsed.types.length === 0) {
  return []; // Ingen type detekteret = intet match
}

// B. Stram filter — KUN denne type, punktum
conditions.push(sql`${products.tags}->>'type' = ANY(${parsed.types})`);

// C. Hvis dette giver 0 resultater → returner 0, ikke fallback

Fejl 3: YOLO + GPT Uoverensstemmelse
Hvad der sker
Table
Komponent	Output	Problem
YOLO (yolos-tiny)	COCO labels: chair, couch, bed	Grov kategorisering, 20 labels
GPT-4o-mini	"grå sofa, scandinavisk stil, stof"	Finkornet, men dansk
Din DB tags	"lounge_chair", "sofa", "scandinavian"	Engelsk, specifik
Tre forskellige navne-konventioner der aldrig mødes.
Løsning: Single source of truth
Brug KUN GPT-4o-mini output til type-beslutning — drop YOLO type til filtering:
TypeScript
Copy
// 1. YOLO detekterer bounding boxes (behold det til crop)
const detections = await yoloDetector(image);

// 2. Crop hvert objekt → GPT-4o-mini analyserer
for (const obj of detections) {
  const crop = await cropImage(image, obj.bbox);
  const vision = await analyzeVision(crop); // GPT-4o-mini
  
  // 3. GPT's type er master — mappet til DB-type
  const dbTypes = mapToDbTypes(vision.types); // dansk→engelsk DB-type
  
  // 4. Søg KUN i denne type
  const matches = await matchProducts({
    types: dbTypes,     // MANDATORY
    colors: mapToDbColors(vision.colors),
    styles: mapToDbStyles(vision.styles),
    materials: vision.materials,
    description: vision.description,
  });
}

// NY SCORING:

score = 
  (color_match ? 50 : 0) +
  (style_match ? 30 : 0) +
  (material_match ? 20 : 0);

Samlet diagnose: Årsagskæde
plain
Copy
Dårlig product match (50-70%)
    ↑
├─ vector_text mangler → søger mod vector_clip (text→image mismatch)
├─ Type-filter er løst → "stol" matcher bogreol
├─ Dansk→engelsk mapping ufuldstændig → type mismatch
├─ Scoring vægter type i stedet for at filtrere den
└─ YOLO og GPT bruger forskellige type-navne
