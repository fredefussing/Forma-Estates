Problem 4: Scoring uden type-vægtning — delvist rigtig
For System B: Type giver 40/100 point, ikke mandatory. En sofa uden farve- eller stil-match scorer 40. En bogreol med perfekt farve+stil scorer 45. Bogreolen vinder. Det er et reelt problem — men kun når type ikke er i fallback (fallback'en er værre).

For System A: Kategori er faktisk mandatory i WHERE (ikke bare en score), bortset fra fallback-scenariet.

Kan de foreslåede løsninger fikse problemerne?
Løsning	Vurdering
Dual-vector (text→text)	✅ Allerede kodet, virker når embeddings er klar
Mandatory type-filter	⚠️ Delvist god, men "returner 0 resultater" er dårlig UX
Single source of truth (GPT)	✅ Allerede implementeret
Ny scoring (farve 50%, stil 30%, materiale 20%)	✅ Forbedring, men mindre vigtig end fallback-fix
Min bedste ide — og jeg er over 90% sikker
Den reelle løsning for System B er en gradueret fallback, ikke "mandatory eller ingenting":

Trin 1: type + farve + stil + pris → søg
Trin 2: < 3 resultater? → behold type, drop farvefilter
Trin 3: < 3 resultater? → behold type, udvid prisinterval ±50%
Trin 4: < 3 resultater? → behold type, drop stil og farve
Trin 5: Stadig < 3? → søster-typer (sofa → lounge_chair, dining_chair → chair)
Aldrig: drop type-filter fuldstændig

Det er bedre end den foreslåede "returner 0" fordi brugerens skærm ikke bliver tom, og bedre end den nuværende løsning fordi type aldrig droppes. Hvert trin logger hvad der sker, så du kan se præcis hvorfor et produkt matchede.
